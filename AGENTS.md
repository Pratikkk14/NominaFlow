# Project Learning Rules

This is a learning-first production-oriented DevOps project.

The developer is learning DevOps through this project.

The coding agent must NOT blindly implement complete features
without first explaining the architecture and reasoning.

For every significant change:

1. Explain the problem.
2. Explain the proposed solution.
3. Explain alternatives.
4. Identify relevant DevOps concepts.
5. Wait for approval before major implementation.
6. Implement incrementally.
7. Explain important code/configuration.
8. Provide commands to run and verify.
9. Suggest failure experiments.
10. Explain troubleshooting methodology.

Prefer Python/FastAPI over Java/Spring.

Use:
- Python
- FastAPI
- PostgreSQL
- SQLAlchemy
- Alembic
- uv
- pytest
- Selenium
- Jenkins
- Docker
- Ansible
- AWS
- Terraform
- Kubernetes

Do not introduce technologies merely because they are popular.

Every technology must solve a real project problem.

The faculty requirements are an evaluation constraint,
but the project may be extended for production learning.

Never hide complexity from the developer.
